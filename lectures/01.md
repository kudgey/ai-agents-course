## Архітектура Transformer

Перш ніж говорити про агентів, треба побачити, що саме працює всередині моделі. Ліворуч — енкодер, праворуч — декодер; сучасні мовні моделі використовують лише праву половину.

## Велика мовна модель як нейронна мережа

Велика мовна модель (*large language model*, LLM) — це нейронна мережа на архітектурі Transformer, навчена передбачати наступний токен за попереднім контекстом. Підручник Jurafsky і Martin дає таке означення:

> *A large language model is a system that can predict the next word for previous words given a context or prefix of words, and use this prediction to conditionally generate text.*

Ключове слово тут «передбачає»: модель повертає ймовірності всіх можливих продовжень, а не одну відповідь. Архітектуру ввела стаття [Vaswani et al., «Attention Is All You Need», 2017](https://arxiv.org/abs/1706.03762); сучасні мовні моделі використовують лише декодувальну половину описаної в ній схеми.

## Архітектура GPT: лише декодер

Моделі сімейства GPT будують зі стека декодерів: кожен токен бачить лише попередні, тому модель придатна саме для послідовної генерації тексту.

## Загальна топологія моделі

Модель складається з однакових блоків, поставлених один на одного. Кожен блок містить механізм attention, який дивиться на всі попередні токени, і повнозв'язну мережу, яка обробляє кожну позицію окремо. Навколо обох стоять залишкові з'єднання (*residual connections*) та нормалізація, без яких глибокий стек не навчається.

Число таких блоків і ширина вектора визначають розмір моделі: у GPT-2 зі 124 млн параметрів це 12 блоків при ширині 768, у моделях класу 70 млрд — 80 блоків при ширині 8192.

Кожен із цих кроків можна покрутити самостійно в інтерактивній візуалізації [Transformer Explainer](https://poloclub.github.io/transformer-explainer/) від Georgia Tech.

## Токенізація: як текст стає числами

Модель не бачить ані літер, ані слів. Токенізатор ріже текст на частини за статистикою навчального корпусу: часті слова лишаються цілими, рідкісні розпадаються на шматки. Українська та інші нелатинські мови дають більше токенів на той самий зміст, і це прямо впливає на ціну запиту та на те, скільки тексту вміститься у вікно.

Порахувати токени можна бібліотекою [tiktoken](https://github.com/openai/tiktoken):

```python
import tiktoken

enc = tiktoken.get_encoding("o200k_base")          # кодування GPT-4o
ids = enc.encode("Асистент навчального відділу")

print(len(ids))                                    # 8 токенів на три слова
print([enc.decode([i]) for i in ids])              # ['Ас', 'ист', 'ент', ' навч', ...]
```

## Embeddings: токен як вектор

Кожен ідентифікатор токена перетворюється на вектор фіксованої довжини — його називають *embedding*. Ці вектори не задають вручну: вони налаштовуються під час навчання так, щоб токени зі схожою роллю в тексті опинялися поруч у просторі.

Один і той самий токен завжди починає з того самого вектора. Контекст ще не врахований — його додають блоки Transformer на наступному кроці. Саме тому статичний вектор слова «замок» однаковий у реченнях про фортецю і про двері, а контекстний — уже різний.

## Таблиця embeddings як пошук за номером рядка

Ідентифікатор токена — це просто номер рядка у ваговій матриці. Однакові токени дають однакові вектори.

## Attention: як модель зважує контекст

Attention дає кожному токену подивитися на всі попередні й зібрати з них зважену суму. Вага пари токенів обчислюється як скалярний добуток запиту й ключа, поділений на корінь із розмірності та пропущений через softmax.

$$\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V$$

| Позначення | Значення |
|---|---|
| $Q$ | запити: що саме шукає поточний токен |
| $K$ | ключі: що пропонує кожен токен контексту |
| $V$ | значення: вміст, який забирається зі знайдених токенів |
| $d_k$ | розмірність ключа; ділення на $\sqrt{d_k}$ утримує softmax від насичення |

## Від логітів до конкретного токена

Останній шар видає по одному числу на кожен токен словника — логіт. Softmax перетворює логіти на розподіл ймовірностей, і вже з нього процедура декодування обирає токен.

## Розподіл наступного токена в коді

Побачити цей розподіл можна безпосередньо через [Hugging Face Transformers](https://huggingface.co/docs/transformers). Код бере невелику відкриту модель, подає їй незавершене речення і друкує п'ять найімовірніших продовжень із їхніми ймовірностями:

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

name = "Qwen/Qwen3-0.6B"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(name)

inputs = tok("Столиця України —", return_tensors="pt")
logits = model(**inputs).logits[0, -1]             # логіти для наступного токена
probs = torch.softmax(logits, dim=-1)              # розподіл над словником

top = torch.topk(probs, 5)
for score, idx in zip(top.values, top.indices):
    print(f"{tok.decode([idx]):<12} {score:.3f}")  # ' Київ' 0.612, ' місто' 0.041, ...
```

## Ймовірність послідовності як добуток

Модель не оцінює текст цілком. Вона розкладає ймовірність усієї послідовності на добуток умовних ймовірностей, де кожен наступний токен залежить від усього попереднього префікса. Цей розклад називають авторегресивним, і саме він робить генерацію покроковою.

$$P(w_{1:n}) = \prod_{i=1}^{n} P(w_i \mid w_{1:i-1})$$

| Позначення | Значення |
|---|---|
| $w_{1:n}$ | послідовність токенів довжини $n$ |
| $w_i$ | токен на позиції $i$ |
| $w_{1:i-1}$ | увесь префікс до позиції $i$ |

Префікс містить і промпт, і те, що модель уже згенерувала сама, тому власна помилка моделі стає частиною умови для наступного кроку.

## Температура як ручка ризику

Температура ділить логіти перед softmax. Менше значення підтягує масу ймовірності до найімовірнішого токена, більше — вирівнює розподіл. Коли $\tau$ прямує до нуля, семплювання вироджується в жадібне; коли $\tau$ дуже велика, розподіл наближається до рівномірного.

$$\mathbf{y} = \text{softmax}(\mathbf{u}/\tau)$$

| Токен | Логіт | $\tau$=0.1 | $\tau$=1 | $\tau$=100 |
|---|---|---|---|---|
| all | 1.2 | .95 | .44 | .25 |
| the | 0.9 | .05 | .33 | .25 |
| your | 0.1 | 0 | .15 | .25 |
| that | −0.5 | 0 | .08 | .25 |

Температура не обрізає хвіст розподілу, а лише перешкальовує його. Обрізанням займаються top-k і top-p, він же nucleus sampling, запропонований Holtzman та ін. у 2020 році.

## Той самий промпт із різними параметрами

Недетермінізм видно на кількох рядках коду. Той самий запит із ненульовою температурою дає різні продовження; з температурою нуль — стабільне, але одноманітне.

```python
from anthropic import Anthropic

client = Anthropic()                               # ключ береться з ANTHROPIC_API_KEY

def ask(temperature: float) -> str:
    r = client.messages.create(
        model="claude-sonnet-4-5",
        max_tokens=64,
        temperature=temperature,
        messages=[{"role": "user", "content": "Одним реченням: що таке токен?"}],
    )
    return r.content[0].text

for _ in range(3):
    print(ask(temperature=1.0))                    # три різні формулювання
```

У прикладі Raschka на GPT-2 зі 124 млн параметрів температура 5 дає продовження «every effort moves you pizza» приблизно у 4 % запусків. Це спроєктована поведінка, а не дефект.

## Порядок документів змінює відповідь

Модель читає контекст нерівномірно. У багатодокументному QA на 2 655 запитах NaturalQuestions-Open змінювали лише позицію документа з відповіддю серед двадцяти уривків, решту умов лишали незмінними.

|---|---|
| Перша з двадцяти | 75.8 % |
| Десята з двадцяти | 53.8 % |
| Двадцята з двадцяти | 63.2 % |
| Без документів узагалі | 56.1 % |

Точність GPT-3.5-Turbo у середині контексту впала нижче за рівень, який модель показує без жодного документа. Той самий набір фрагментів, поданий в іншому порядку, дає іншу відповідь, тому склад і порядок контексту фіксують так само строго, як температуру. ## Версія моделі й мовчазні налаштування

Друге джерело розбіжності живе не в запиті, а в середовищі. Та сама модель під іншим обв'язуванням дає інший результат: за оцінкою Epoch AI вибір харнесу змінює результат на SWE-bench Verified до 20 відсоткових пунктів, через що числа різних команд між собою непорівнянні.

Локальні дефолти діють так само тихо. В [Ollama](https://docs.ollama.com/faq) змінна `OLLAMA_CONTEXT_LENGTH` за замовчуванням дорівнює 4096, і довші промпти обрізаються без жодного повідомлення, а `OLLAMA_NUM_PARALLEL` дорівнює 1, тобто сервер з коробки взагалі не батчить. Версія моделі, параметри декодування й ліміти контексту належать до конфігурації системи і мають жити в репозиторії поруч із кодом.

## Батч, залізо і рухома кома

Додавання чисел з рухомою комою не асоціативне, тому результат суми залежить від порядку доданків. Монографія Xiao і Zhu фіксує наслідок для розподіленого навчання:

> *slight numerical differences in accumulated gradients on different nodes* … *inconsistencies across different hardware devices*

Механізм той самий скрізь, де сума збирається паралельно. Додайте до цього планування на рівні ітерації: сучасний сервер щокроку перескладає батч із тих запитів, які саме зараз у черзі, тож ваш запит рахується в різному оточенні залежно від навантаження. Біт-у-біт однакового виходу на різному залізі очікувати не варто, і тести пишуть із цього припущення.

## Дев'ять компонентів і їхня зона відповідальності

Кожен компонент ламається по-своєму, і кожному в курсі відведено окремі лекції.

## Хто визначає послідовність кроків

Anthropic розділяє агентні системи на два класи за тим, хто визначає послідовність кроків:

> *Workflows are systems where LLMs and tools are orchestrated through predefined code paths.* … *Agents are systems where LLMs dynamically direct their own processes and tool usage.*

Різниця операційна: у workflow кількість кроків відома на етапі проєктування, в агента вона невідома до запуску. Порада авторів звучить прямо — починати з найпростішого рішення і додавати складність лише за потреби, «*this might mean not building agentic systems at all*». Курс повертається до цієї межі в блоці D, коли з'явиться чим виміряти ціну автономії.

## Шість критеріїв вибору моделі

Жодного з них не досить окремо, і публічний бенчмарк каже про вашу задачу мало. Тому перший критерій починається з власного набору задач.

1. **Якість на вашій задачі** — вимірюється на власному golden set, не на публічному лідерборді.
2. **Затримка** — TTFT і час на токен під реальним навантаженням, а не в одиночному запиті.
3. **Вартість** — за мільйон токенів і, важливіше, за одну успішно розв'язану задачу.
4. **Приватність даних** — де фізично виконується запит і що записується в логи постачальника.
5. **Ліцензія** — що саме дозволено в продакшні; це інженерне обмеження, а не формальність.
6. **Контекстне вікно** — скільки токенів реально обслуговується, а не заявлено в анонсі.

Останній критерій оманливий найчастіше. Llama 4 Scout заявляє 10 млн токенів контексту, але за ілюстративною геометрією моделі класу 70B це близько 3 ТіБ KV-cache, тобто число номінальне, а не обслуговуване.

## Ціна тієї самої точності

Вартість задає не лише модель, а й обв'язування навколо неї. Порівняння на HumanEval з GPT-4, по п'ять прогонів на кожну систему, показує розрив майже на два порядки при близькій точності.

| Система | Точність | Вартість прогону |
|---|---|---|
| GPT-4 zero-shot | 89.6 % | $1.93 |
| Warming | 93.2 % | $2.45 |
| Reflexion | 87.8 % | $3.90 |
| LATS | 88.0 % | $134.50 |

Найдорожча конфігурація програє найкращій 5.2 відсоткового пункта і коштує у 55 разів більше. Без колонки вартості ця таблиця виглядала б як успіх складної архітектури. Джерело: [AI Agents That Matter](https://arxiv.org/abs/2407.01502).

## Демонстрація працює, система не працює

Демонстрація показує, що система спрацювала хоч раз; продакшн вимагає, щоб спрацьовував кожен запит. Ці два погляди дають різні метрики: pass@k росте з кількістю спроб, а pass^k — ймовірність успіху всіх k прогонів — спадає.

| Спостереження | Число | Умови |
|---|---|---|
| pass^1 проти pass^8 | ≈ 61 % проти ≈ 25 % | GPT-4o, τ-bench retail |
| агент проти людини | 14.41 % проти 78.24 % | WebArena, 812 задач |
| некоректні розв'язки | 24 % топ-50 | SWE-bench Verified, аудит |
| локалізація файлів | 63–65 % проти 12 % | лише текст тікета, свіжі репо |

Останній рядок особливо неприємний: на свіжих репозиторіях та сама модель знаходить потрібні файли вшестеро рідше, і це сигнал запам'ятовування, а не здатності.

## Мінімальний цикл оцінювання

Оцінювання починається не з фреймворку, а з двадцяти рядків, які проганяють набір задач і рахують частку успіху. Усе інше — надбудова над цим циклом.

```python
import json
from anthropic import Anthropic

client = Anthropic()
tasks = json.load(open("golden_set.json"))         # [{"q": ..., "must_contain": ...}]

passed = 0
for t in tasks:
    answer = client.messages.create(
        model="claude-sonnet-4-5",
        max_tokens=256,
        temperature=0,                             # фіксуємо семплювання
        messages=[{"role": "user", "content": t["q"]}],
    ).content[0].text
    passed += t["must_contain"].lower() in answer.lower()

print(f"task success: {passed}/{len(tasks)} = {passed / len(tasks):.1%}")
```

Вихід — одне число, яке порівнюють між версіями системи: `task success: 63/80 = 78.8%`.

## Межі курсу

Курс не вчить тренувати моделі з нуля: pre-training з'явиться в лекції 03 рівно настільки, наскільки він пояснює поведінку готової моделі. Курс не досліджує архітектури і не оцінює їхню наукову новизну — Transformer тут інструмент, а не предмет вивчення.

Курс не є юридичною консультацією: ліцензії ми читаємо як інженерне обмеження на збірку й постачання, а рішення про комерційне використання ухвалює юрист компанії. Поза межами лишається і безпека моделі як предмет вирівнювання — ми будуємо безпеку системи навколо моделі, вважаючи саму модель даністю.

## Висновки

Велика мовна модель — це стек блоків Transformer, який перетворює токени на розподіл ймовірностей наступного токена; відповідь будується по одному токену, і кожен обраний токен стає частиною умови для наступного.

Через це та сама пара входу й параметрів законно дає різні виходи. Недетермінізм має п'ять окремих джерел, і лише частина з них вам належить. Модель — одна деталь із дев'яти, і вісім інших визначають, чи витримає система користувачів. Вибір моделі ухвалюють шістьма критеріями разом, серед яких ліцензія стоїть нарівні із затримкою. Оцінювання проєктують до першого промпта, бо без golden set будь-яка зміна системи лишається питанням смаку.
