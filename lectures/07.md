## Чого ви навчитеся

Після цієї лекції ви зможете:

1. Пояснити, які дві пам'яті з'єднує RAG і що дає кожна з них.
2. Назвати шість полів метаданих чанка і сказати, яку операцію вмикає кожне.
3. Обрати стратегію чанкінгу під тип запитів і обґрунтувати вибір числами.
4. Реалізувати citation grounding як контракт коду, а не прохання в промпті.
5. Локалізувати помилку пайплайна за симптомом до конкретного етапу.

## Дві пам'яті в одній системі

Оригінальне означення звучить так:

> *Models which combine pre-trained parametric and non-parametric memory for language generation.*

RAG (*retrieval-augmented generation*) означає з'єднання двох пам'ятей. Параметрична пам'ять — це ваги моделі. Непараметрична — щільний векторний індекс, доступний через ретривер.

Перша пам'ять зафіксована навчанням і мовчить про те, звідки взяла факт. Друга оновлюється заміною документа й завжди може показати, звідки саме відповідь. Джерело — [Lewis та ін., 2020](https://arxiv.org/abs/2005.11401).

## Одна формула, яку варто прочитати

Модель не обирає один документ, а усереднює свій вихід по кількох знайдених, зважуючи кожен імовірністю, яку йому дав ретривер. Сума по документах і є всім змістом формули: генерація відбувається **за умови** знайденого тексту, а не замість нього.

$$p_{\text{RAG-Sequence}}(y \mid x) \;\approx\; \sum_{z \in \text{top-}k(p(\cdot\mid x))} p_\eta(z \mid x)\, p_\theta(y \mid x, z)$$

| Позначення | Значення |
|---|---|
| $x$ | запит користувача |
| $y$ | згенерована відповідь |
| $z$ | окремий знайдений пасаж |
| $p_\eta(z \mid x)$ | ретривер: розподіл над пасажами |
| $p_\theta(y \mid x, z)$ | генератор за умови пасажа |
| $\text{top-}k$ | $k$ найімовірніших пасажів замість усієї колекції |

## Naive, Advanced і Modular RAG

Пайплайни різняться не наявністю пошуку, а кількістю рухомих частин навколо нього. Naive RAG «follows a traditional process that includes indexing, retrieval, and generation». Advanced RAG вносить покращення до і після пошуку. Modular RAG робить кроки окремими модулями, які можна міняти місцями.

## Метадані є частиною чанка

Чанк без метаданих не можна ні відфільтрувати до пошуку, ні процитувати після нього, ні видалити, коли документ скасували. Це три різні операції, і кожна потребує свого поля, записаного під час ingestion.

Права доступу застосовують **до** пошуку, а не до відповіді. Фільтр після генерації означає, що модель уже прочитала документ, якого не мала бачити.

## Ingestion у коді

Парсинг, чанкінг і метадані одним проходом. Кожен чанк несе все, що знадобиться для фільтрації, цитування й видалення:

```python
from dataclasses import dataclass, asdict
import pypdf, tiktoken

enc = tiktoken.get_encoding("o200k_base")

@dataclass
class Chunk:
    text: str
    doc_id: str; source: str; section: str        # для цитати й видалення
    valid_from: str; access: str; version: str    # для фільтрації до пошуку
    score: float | None = None                    # заповнює ретривер, не ingestion

def ingest(path: str, doc_id: str, meta: dict, size=512, overlap=64) -> list[Chunk]:
    out = []
    for page_no, page in enumerate(pypdf.PdfReader(path).pages, start=1):
        ids = enc.encode(page.extract_text() or "")
        for start in range(0, len(ids), size - overlap):        # крок = 448 токенів
            piece = enc.decode(ids[start:start + size])
            if len(piece.strip()) < 80:                          # порожні хвости відкидаємо
                continue
            out.append(Chunk(text=piece, doc_id=doc_id,
                             source=f"{path}, с. {page_no}", **meta))
    return out

chunks = ingest("nakaz-112-06.pdf", "наказ 112-06",
                {"section": "розділ 3.2", "valid_from": "2025-09-01",
                 "access": "public", "version": "v3"})
print(len(chunks), asdict(chunks[0])["source"])    # 47 nakaz-112-06.pdf, с. 1
```

## Sentence-window і parent-document

Обидва патерни розводять те, що індексують, і те, що показують моделі. Перший індексує окреме речення, а в промпт кладе вікно сусідніх. Другий індексує дрібний чанк, а в промпт підставляє батьківський розділ.

## Промпт складають у сталому порядку

Базовий алгоритм має рівно три кроки: викликати ретривер по $k$ пасажів, скласти промпт із пасажів і запиту, викликати модель. Канонічна схема: спершу знайдені пасажі один за одним, потім рядок інструкції, потім питання.

Кожен пасаж входить **разом зі своїм ідентифікатором**, інакше цитувати буде нічим. Порядок фрагментів не є нейтральним: на двадцяти документах у контексті розрив між першою і десятою позицією сягав 22 пунктів, і лекція 04 розібрала цю криву детально.

## Citation grounding як контракт

Grounding означає, що кожне твердження відповіді має вказівник на конкретний чанк, а не на документ загалом. Це перевіряється **кодом до показу відповіді**.

## Генерація з перевіркою цитат

Той самий контракт із лекції 05, тепер над знайденими чанками. Ключова частина — валідація **після** генерації, яка має право не пропустити відповідь:

```python
from anthropic import Anthropic
client = Anthropic()

def answer(question: str, hits: list[Chunk]) -> Answer:
    if not hits or hits[0].score < 0.45:                    # поріг на власному наборі
        return Answer(answer="", citations=[], confidence=0.0, abstained=True)

    docs = "\n\n".join(f"[{i}] ({c.doc_id}, {c.source})\n{c.text}"
                       for i, c in enumerate(hits, 1))      # ← id у кожному пасажі
    payload = call_with_schema(client, SYSTEM, f"<documents>\n{docs}\n</documents>\n\n"
                                               f"Питання: {question}")
    ans = Answer.model_validate(payload)

    # звіряємо не лише документ, а й те, що цитований текст справді є в поданому чанку
    known = {c.doc_id: c.text for c in hits}
    ans.citations = [c for c in ans.citations
                     if c.doc_id in known and c.quote[:40] in known[c.doc_id]]
    if not ans.citations:                                   # нічим підтвердити → відмова
        return Answer(answer="", citations=[], confidence=0.0, abstained=True)
    return ans
```

Рядок із `known` ловить найнебезпечніший випадок: модель повертає правильну на вигляд відповідь із цитатою на документ, якого їй не давали.

## Чотири типові відмови

**Правильний чанк не знайдено** — помилка пошуку, видно лише на розмічених запитах. **Чанк поданий, але модель відповіла з ваг** — промпт із одним цим чанком показує це за одну спробу.

**Відповідь правильна, а цитата її не підтверджує** — найнебезпечніший випадок, бо система виглядає перевіреною. **Застарілий документ в індексі** дає правильну цитату на скасовану норму: скасований наказ, який лишився в індексі, гірший за відсутній.

У корпусі з послівними анотаціями найчастішим типом помилки виявилась не суперечність контексту, а безпідставно додана інформація, і ловить її саме звірка цитат.

## Межі лекції

RAG не робить модель правдивою. Він переносить джерело помилки з ваг на індекс: тепер неправильна відповідь найчастіше означає неправильний, обірваний або скасований документ, і полагодити це можна без донавчання.

Галюцинації при цьому не зникають: виміряна щільність на корпусі з наданим контекстом становить 0.06 для GPT-4-0613 і 0.59 для Mistral-7B-Instruct, тобто вибір моделі генерації досі важить. Формула маргіналізації сьогодні має концептуальне значення: промислові системи кладуть пасажі в промпт, а не сумують по документах. Числа contextual retrieval виміряні однією командою на власних наборах.

## Висновки

RAG з'єднує дві пам'яті: ваги моделі та зовнішній індекс, і саме друга дає можливість оновити знання заміною документа й показати джерело. Ingestion не є технічною преамбулою: метадані джерела, розділу, дати чинності й прав доступу вирішують, чи буде взагалі можлива фільтрація, цитування і видалення застарілого.

Універсального розміру чанка немає, бо оптимум залежить від типу запитів і від моделі embeddings, а дописаний контекст знижує частку невдалих пошуків з 5.7 % до 2.9 % без зміни моделі генерації. Citation grounding є контрактом коду, а не проханням у промпті, і відмова при порожньому пошуку є нормальною поведінкою системи. Помилка локалізується за симптомом у чотирьох етапах, і без цієї локалізації правки промпта є вгадуванням.
